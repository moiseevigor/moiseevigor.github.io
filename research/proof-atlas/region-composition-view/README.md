# Inspecting scope-correct output groupings

The existing [paged reader](/projects/proof-atlas/manual/paged-network/) now exposes the checked flat/grouped output rule. Load a recorded result collection, choose **Group output collection**, then select a grouping or a typed adapter. The original source-use graph remains the graph of applications; the new panel represents output positions and computed maps.

Three exact collections have nine groupings: Riccati's seven-output AM–GM selection, the distinct-scope `37,44,75` selection, and eight recorded AI-source outputs. This is 54 position appearances at 17 distinct original occurrences. The other eighteen native cases from the [underlying experiment](../region-output-composition/README.md), including its dependent/mixed-sort controls, remain research checks and are not added to the browser inventory.

## Visual rule

- Flat and grouped positions highlight together and retain their original result address. The selected original-context statement appears once. An explicit source portal opens that occurrence.
- Γ names the exact shared source prefix. `C1`, `C2`, etc. identify different original context paths in the current collection. Equal depth or binder names do not merge contexts. Extra source frames show four at a time, with exact header portals; domains and let values keep their pre-binder scope.
- `flatten : H → F` and `gather : F → H` are recorded typed functions. Their arrows are distinct from source-use edges and output correspondence. The explicit kernel type-comparison result is shown separately; convertible types do not merge output positions.
- One selected tuple or adapter has separate term/type roots. The existing constructor notation shows at most four vertices around the selected computed field, with lexical links either to a computed binder or to an original Γ binder. The selected root owns a recorded typing judgment; descendants have syntax and scope information only.

Computed addresses use `scope-output-composition` with the native evidence, component file, case, term/type component and ordered field route. They never acquire an invented original-proof occurrence. Computed-field navigation preserves the original source selection. Graph-source clicks update the output position when it belongs to this collection; an outside selection is explicitly unmatched. Grouping mode and grouping choice survive a source-use fold. A changed cut retires the computed field lease; field paths currently reopen at the component root.

## Delivery and lifetime

The generator pins native data to commit `02c828c00c368987a9940a66cfa88635f76e8041`. A small index binds each exact source collection to its older checked output closure, three groupings, native round-trip records and an explicit successful kernel comparison. Source frames and original occurrences come from an owned, live output session that has already checked source pages. An arbitrary object with matching strings cannot supply that capability.

Only the selected computed component loads: one DAG with term/type roots, capped at 4,096 stored rows and 1 MiB decoded JSON. Metadata has a 256 KiB index cap and a 2 MiB source-scope cap. Opening grouping releases the preceding individual-result type graphs. Returning to the individual view loads its own two bounded graphs again. Parent disposal cancels the grouping and releases its metadata and graph. The independently selected source inspector has its existing separate bounds; these are not whole-browser memory measurements.

There are 39 content-addressed delivery assets: three indexes and 36 component files. The largest finite component has 2,437 rows. No complete original source archive, native batch or experimental native package is requested by this runtime. Native typing and conversion belong to the pinned Lean records; JavaScript checks delivery, exact source bindings, context paths, graph structure and displayed scope. It does not rerun the Lean kernel.

Unrecorded collections and source-only cuts have no invented grouping. Optional failures preserve the source reader and individual results. Component failures have retry. Late or detached controls cannot restore an old case, source selection or proof profile. The original proof source scripts and checking binaries are not published.

## Checks

[Model report](model-check.json.gz) checks all nine cases and 36 components against the native graphs, ordered original ports, source-header paths and an independent lexical-stack walk. It covers 133,973 node/depth cuts, 5,172 original Γ links and 2,011 computed binder links; this is a finite audit using complete offline reference data. It also checks forged parents, stale receipts, cancellation, component corruption and altered metadata. The equal-depth Riccati diagnostic retains three distinct context labels.

Production browser, delivery and compatibility reports are retained with [aggregate fingerprints](evidence.json.gz). Browser checks exercise all groupings and component roots, actual source and binder jumps, graph-to-output selection, folding, failure/retry, stale work, keyboard access, desktop/phone layouts and both themes. Component and metadata bounds are checked separately from view-size limits. Broader corpus coverage, semantic compression, arbitrary boundary substitution and measured human comprehension remain open. No blog update accompanies this integration.

The production grouping run inspects 72 term/type roots, preserves 36 original source selections during computed navigation, and checks 54 output-position selections. Four desktop/phone and light/dark accessibility audits report no violations. Compatibility reruns cover the earlier reader's eighteen output positions and 36 type views, the source-context sheet, and the existing source-use network. These are finite software checks; the native laws and typing records are unchanged.
