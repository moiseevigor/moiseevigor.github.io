# Rule heads and proof arguments

A proof-valued function is still an input to an application. Showing only supplied proof arguments leaves `f : P → Q` outside that focused view even though `f p` uses both `f` and `p`. This extension partitions every original position at a retained region boundary into **function heads**, **recorded proof-valued arguments**, and **other arguments**. Function slot zero remains distinct from every supplied argument.

## Source rule and recovery

The proof-source pool includes both recorded proof-valued heads and recorded proof-valued arguments. It bundles positions only when their exact original lexical binder, or resolved producer occurrence and original context, agrees. The qualifier includes the compiled packet, declaration, root/slot route, native observation owner and finite source-use inventory. One source may appear in both roles. Each use keeps its original consumer slot and its own typing observation; a common source does not merge computed type addresses.

The three position classes are disjoint and recover the complete ordered boundary. For a native region:

    boundary positions = function heads + proof arguments + other arguments
    proof-support positions = proof-valued heads + proof arguments

These are source/role identities, not a theorem that the displayed objects are a minimal or sufficient mathematical premise set. Value and type inputs may affect a proof. The region still has separate original contexts and result portals; it does not acquire a common-context sequent or a new composite typing judgment. Complete-inventory acyclicity remains an independent graph check.

The Riccati seven-call region has **35 boundary positions = 7 heads + 5 proof arguments + 23 other arguments**. All seven heads are recorded as proof-valued, so the full native proof-source pool contains twelve positions. The earlier five-argument projection remains available and is now explicitly named **Proof arguments**. The heads of the three `Eq.mp` and three `congrArg` calls remain separate source occurrences rather than being merged by their declaration names.

## Callable type and literal syntax

A head summary retains three separately addressed observations:

1. The original producer type in its original producer context.
2. The literal function-input type in the consumer context.
3. The recorded weak-head-normalized function-input type in the consumer context.

The third graph must have a `forallE` head and retain its native conversion owner. This establishes observed callability, not that every `forallE` is a proof. The proof/value role is taken from the native observation and checked separately. A proof application requires a recorded proof-valued head and a recorded proof-valued result.

A normalized type never acquires an invented source route or a literal formal binder. If the literal type is an alias and its formal-domain prefix is unavailable, the reader keeps that boundary explicit. It shows the recorded callable type in a separate computed namespace. The existing observed argument window remains bounded; unvisited formal slots are not claimed to have been reconstructed.

## Fresh controls

Three authored Lean 4.33.1 controls pass fresh closed-root checking and packet-only replay of four calls and eight actual ports. Original declarations/modules are absent from replay. Restored dependency binaries are hash-checked; this is not an independent Lean/Mathlib rebuild.

- `aliasProof`: the literal head type is the local alias `F`. Its native callable head type is `P → Q`; the head is proof-valued and the result is a proof of `Q`.
- `aliasValue`: the same surface alias spelling `F` has native callable type `ℕ → ℕ`. This is a value function and its result is a value. Neither the string `F` nor the `forallE` head constructor supplies proof classification.
- `bothRoles`: `f (h f)` uses the same original `f : P → Q` as argument `0:1` and function head `1:0`. The three proof-valued boundary positions form two source bundles. The two uses of `f` keep distinct original query/type addresses. The producer-to-consumer source graph remains acyclic.

Only authored synthetic source, compiled observations and review metadata are added. Private research proof scripts and raw execution logs remain outside publication.

## Reader and bounds

The boundary selector offers proof arguments, function heads and all original input positions. In a native region with no supplied proof arguments, the head view provides typed function information. In source-only records, native roles and callable types remain unavailable; the full source-position view stays available.

A selected head marks its actual consumer call and opens that exact original input. **Literal function type** and **Callable head type** select their separate original native computed roots. Switching views preserves the current selected source/type lease. A shared proof-source badge is the same in the argument and head views, including the dual-role control.

The support model is capped at 4 MiB. A head summary page has at most four positions and 4 MiB of summary rows. The loader opens one existing native inspector window at a time, checks original/literal/normalized roots, text, roles and contexts, then disposes that window. A window may have up to five fully resident computed graphs under the existing inspector bounds. Completed summary pages retain no computed graphs. The independently selected inspector remains a separate lease. These are component bounds, not a total heap measurement. No complete source archive or native batch is requested by this loader.
