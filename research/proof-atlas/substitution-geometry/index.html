Visual notation manual / Substitution

Follow a replacement through its binders

Substitution replaces an external reference with an expression. A replacement entering local binders must keep its own bindings and shift its external indices. The same stored variable can therefore mean different things at different occurrences.

$$\operatorname{subst}_{\sigma,d}(\operatorname{bvar} i)=\begin{cases}\operatorname{bvar}i&i<d,\\\operatorname{shift}_{d}(\sigma_{m-1-(i-d)})&d\leq i<d+m,\\\operatorname{bvar}(i-m)&i\geq d+m.\end{cases}$$

Here d counts binders below the selected source root; the m replacements are ordered from the oldest context entry to the newest. Lambda and Π bodies, and let bodies, add a binder. Their domains and let values do not. A shift also respects binders inside its replacement.

The path rule

Write at(e,p) = (u,d) when ordered field path p selects expression u at local binder depth d. Here S is a de Bruijn-indexed substitution: the reader's source-ordered images define S(j) = σ[m−1−j] for j < m, and bvar(j−m) otherwise.

$$\operatorname{at}(e,p)=(u,d)\ \Longrightarrow\ \operatorname{at}(\operatorname{subst}_{S}e,p)=(\operatorname{subst}_{\uparrow^{d}S}u,d).$$

A valid source path survives substitution. When it reaches an external reference, a selected image fragment needs a second path q. If at(e,p) = (bvar i,d), d ≤ i and at(S(i−d),q) = (v,k), then:

$$\operatorname{at}(\operatorname{subst}_{S}e,p\mathbin{\cdot}q)=(\operatorname{rename}_{\uparrow^{k}(+d)}v,d+k).$$

The image's own local binders are counted by k. Their references stay fixed; external image indices shift by d. A source-local binder owner keeps its original path under substitution. An image-local owner at b moves to p·b. Names alone never identify the binder.

These are kernel-checked laws on actual Lean.Expr, with a proved postorder graph selector. They do not prove the JavaScript or JSON adapter. The finite bridge independently checks the recorded paths and field convention. A coherent application-port swap still satisfies the path laws but fails that wire check.

Two scope controls

One row, two scopes. In app (bvar 0) (λ x : Nat, bvar 0), the first reference takes the supplied replacement. The second is bound by x. Sharing their stored row does not identify their occurrences.

An open image. Insert λ z : Nat, B₉₀ (bvar 1) (bvar 0) under λ y : Nat. The result keeps the image-local bvar 0 and shifts its external reference to bvar 2. Here B₀(a,b) = app a b and Bₙ₊₁ = app Bₙ Bₙ. The result has exactly 2⁹² + 3 occurrences in 96 reachable stored rows. This authored expression-data control has no asserted mathematical typing.

Evidence and scope

All 2,835 queries from the certified substitution experiment are available, including all six Riccati source/template openings. Query indices are examples and repeated views, not independent proofs. Only one publisher-attributed AI proof is included.

The path-law bridge checks those queries and three separate authored controls: created result fields, repeated image uses and residual context. Its 28 checked theorems include two concrete counterexamples. The interactive catalogue remains the original 2,835-query cohort; the new controls have reproducible native/model records.

The executor's native return proofs were erased; per-input proof terms were not independently rechecked. This browser checks hashes, visible field correspondence, binding paths and exact occurrence accounting. It supplies no new descendant typing or claim about mathematical necessity or readability. General JavaScript/JSON refinement and mathematical typing preservation remain open.

The reader keeps one 64-row syntax cache, two index pages and one query record. Visible cuts have at most twelve vertices; paths stop at 512 fields. Reference discovery uses a separate bounded row/depth search. These are explicit retained-data limits, not a measured bound on total browser memory. Original query and proof-context identities remain separate from pooled syntax.
