# Recorded producer-to-input type bridges

A source-use wire identifies an original producer and consumer slot. It does not show how the producer's type relates to the domain expected at that slot. The paged construction reader and individual-application reader now share one visual rule for that relation.

## Three original observations

Each recorded native input exposes:

1. `producerType`, in the original producer context.
2. `producerTypeInConsumer`, obtained by the recorded literal context extension.
3. `inputType`, the expected domain at the actual consumer input, in the consumer context.

Every stage retains its original native owner, source identity, call query, input slot, component and computed root address. Its context has a qualified original source owner as well as a length. The bridge has a separate `application-input-type-bridge` identity; it does not acquire an original source-expression address. Selecting a stage opens that recorded type root and leaves the selected source construction unchanged.

The first relation is the existing checked literal weakening. The second is a recorded kernel conversion between the lifted producer type and the expected input type. Both come from the pinned native observation. The browser separately compares literal expression structure in the common consumer context. A structural difference does not imply a failed typing check. Equal printed strings do not establish structural equality.

The visual component displays all three stages when contexts differ. With zero context extension and equal recorded display strings, it displays one formula with separate original and lifted selectors. These remain two addresses and two context-owner records. The expected type remains a separate port. This is a presentation fold, not a new typing judgment or a merged source occurrence.

In the folded graph, **Compare input types** opens the selected input's bridge. **Return to selected input** returns to its reference path. In the individual-application reader, the same control is available for each loaded function/argument slot. The existing graph, source controls and type controls remain usable if the optional visual component cannot load. Source-only inputs have no bridge or enabled comparison control.

## Context correction

The shared application-query provider previously returned the consumer context length for every computed root. The network inspector corrected original-producer roots locally, but individual-application callbacks received the consumer length. The provider now returns the original producer context for `producerType` and the consumer context for the other roots. It also returns the exact context owner. The network inspector checks this shared contract rather than silently replacing it. This matters at the 37 inventoried inputs whose producer and consumer contexts differ.

## Literal comparison rule

The two compared roots already inhabit the same recorded consumer context. Compare ordered constructors, canonical payloads and child pairs without shifting variable indices or tracking an additional binder depth. Equal node IDs within that same validated graph are reflexive structural matches. They do not choose a source producer or identify binders across contexts.

The comparison visits at most 262,144 distinct stored node pairs. Exceeding the pair budget returns **literal comparison unavailable**, retaining the separately recorded conversion status. It does not assume equality or inequality from printed text. With constructor arity at most three, its pending work is bounded by twice the pair limit plus one. These are component bounds; the original source/native window bounds remain separate.

An authored, structurally validated control has 2,050 stored nodes and two isomorphic shared roots, each representing a 155-digit number of expression occurrences. A general comparison that retains binder depth exceeds its 262,144-state budget on this control. The common-context comparison visits 1,025 stored pairs and agrees with an independent Merkle fingerprint. A reduced eight-pair budget produces an explicit unavailable state. This control is not a kernel-checked proof or an AI-generated proof benchmark. The improvement is local to this comparison. Existing weakening validation still uses the earlier depth-tracking comparator and can reach its separate budget.

No additional native graphs or source archives are loaded for the bridge. Its three display strings retain the existing 262,144 UTF-16-code-unit field bound. The individual-application view retains one bridge presentation at a time and clears it on a window change. This change does not make the underlying computed graphs paged or establish a total browser-heap bound.

## Finite observations and checks

The [model checker](check-model.cjs) checks all **877 native inputs in 42 profiles** against the pinned native batches. Independent context-sensitive Merkle fingerprints verify the original-to-lifted weakening and classify the lifted/expected pair. It checks 2,631 type-root selections, complete source/query/slot ownership and original context owners.

| Observation | Inputs |
| --- | ---: |
| Same literal structure in consumer context | 792 |
| Different structure, recorded kernel conversion passes | 85 |
| Of those differences, printed strings are identical | 37 |
| Producer and consumer context lengths differ | 37 |

These are observations of this selected inventory, not a new theorem about Lean. In the Riccati example, input `25:3` receives an equality produced by `congrArg`: the recorded producer type retains applications of a lambda, while the expected domain displays the substituted expression. At input `26:4`, the displayed strings agree while their recorded type structures differ. Input `25:4` demonstrates the original Γ10 to consumer Γ13 extension.

Fifteen negative/budget controls cover altered conversion checks, incorrect weakening, changed contexts, foreign computed addresses and invalid comparison bounds. Six selected inputs in the larger source-only packet retain no fabricated type bridge. This does not check every input in that packet.

The [browser checker](check-browser.cjs) compares identical native bridge data across the paged and individual readers, exercises eighteen type-root selections and three library selections that preserve the source route, checks both context layouts, and tests source-only and missing-component behavior. Eight desktop/phone and light/dark accessibility audits cover both shared presentations. Explicit checks keep the type heading below the fixed navigation and use interface typography; the selected stage is marked by its full computed address, including its component. Six isolated renderer controls reject mixed or unrecorded observations; an authored presentation fixture tests the unavailable comparison label separately from native results.
