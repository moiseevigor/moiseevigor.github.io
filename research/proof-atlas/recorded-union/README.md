# Recorded evidence at an exact occurrence

Status: local research result. No new Lean execution, blog post or deployment.

## Representation rule

The occurrence reader previously opened primary typing records and a separate
local-definition supplement. An application could therefore have recorded inputs
in the binding inspector and ordinary proof diagram while remaining an untyped
boundary in the occurrence diagram.

The complete occurrence reader and the sparse page producers now use the same
finite union of published compiled records. Identity is the declaration, edition,
compiled packet and exact occurrence route. A shared storage node is insufficient.
At overlapping routes, the selected source node, proof/type/value role, ordered
original context and type expression syntax must agree. Definitional equality is
not used to excuse a syntactic disagreement. A disagreement rejects the union.

A checked primitive construction precedes a plain type observation. Ties use the
fixed order case, beta, let, primary, packet replay, immediate-use record. These
are evidence providers, not new geometric primitives. Every application retains
its function and argument ports, source context, conclusion and conversion
records. Introductions and local definitions retain their distinct field rules.
Specialized case and reduction interpretations remain in the ordinary reader;
this union supplies primitive occurrence constructions.

The selected construction retains its original sealed owner. A separate ledger
lists the alternatives at the position, with each archive hash, query route and
type identity. Forming the union does not relabel or mutate its input records.
Public replay metadata and privately recompiled Riccati metadata remain distinct.

## Finite result

The union contains **5,568 typed positions and 2,527 primitive constructions in
35 profiles**, compared with 2,442 positions and 1,084 constructions in the older
26-profile primary/let transport. The expanded set includes recursion controls;
these totals are not additional independently generated proofs.

All **448 overlapping observations** agree. The independent audit checks 6,016
input observations and 64,446 ordered context slots against source-field walks.
It compares all six application type components at each of the **283 immediate
application sites** with the ordinary reader: 1,698 component comparisons.

In Lemma 3.2, the recorded consumers `JacobiData.T1_T2_same_sign` (e1298) and
`abs_of_pos` (e2333) expose their proof input `hd : 0 < J.d p` in both occurrence
transports. The published Riccati profile contains 752 typed positions and 356
primitive constructions; the separately labelled working profile has 201 and 90.
These are finite recorded subsets, not full native typing coverage.

The AI-attributed example `lean_workbook_plus_43987`, e78, applies the local
hypothesis `∀ (k : Fin n), ‖z k‖ = ‖omega k‖` to a value `k : Fin n`. Its function
and result have proof roles while its argument has a value role. The source
binder link and the application type components are preserved.

## Delivery and limits

The sparse transport indexes all union positions. Up to eight type-table
descriptors may be listed (five occur in this sample); selecting a type opens
one active type table. Record, index, source and type page caches retain their
existing caps. Tests also exercise one-page source and type caches. Sparse
navigation does not request the complete evidence archives. The explicitly
selected complete transport loads its bounded archives and makes no whole-proof
resident-memory claim. A failed input rejects the combined native profile; source
navigation remains available and the profile can be retried. Partial metadata
is not silently presented as an accepted union.

This is a consistency result for compiled attestations and finite representations.
It is not a portable kernel certificate, a new proof of the Riccati theorem,
premise-necessity analysis, semantic compression or a comprehension result.
The original mathematical source projects and tactic scripts remain private.
Native execution and dependency-cache attribution retain the limits in the
[immediate-site verification](../use-sites/native-verification.json).
