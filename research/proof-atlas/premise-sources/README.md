# Proof-valued inputs with original source bundles

An application region can have many boundary positions without having many proof-valued arguments. The Riccati seven-call region has 35 boundary positions: seven function heads, twelve type arguments, eleven values and five proof arguments. Showing the first four positions mainly exposes function/type plumbing. The optional proof-input view instead shows the recorded propositions of the five proof arguments. Every original input remains available under **All input positions**; this is a reversible presentation projection, not a smaller mathematical interface.

## Rule

Select actual boundary arguments whose recorded native role is `proof`. Function slot zero remains a separate category even when its own term is proof-valued. Source-only records have unobserved roles: they retain the full input view and cannot report a discovered zero-premise interface.

Two selected positions share a displayed source bundle only when their original lexical binder is identical, or their resolved producer occurrence and original context are identical. Qualify that identity by compiled packet, declaration, root/slot route, native evidence owner and inventory. A stored node ID, proposition string or type conversion alone is insufficient. Every use retains its ordered consumer position, input occurrence, producer occurrence, original contexts and local-definition path. Grouping sources does not identify all their type judgments or merge argument positions.

The projection partitions the original boundary into proof positions and other positions. Expanding it reconstructs the complete ordered boundary. A bundle has a derived namespace and hash; it does not acquire an invented Lean expression address. The enclosing region's complete-inventory graph check remains separate. This projection adds neither a common-context sequent nor a native judgment for a composite region.

## Native counterexamples

Two authored Lean 4.33.1 controls pass fresh closed-root checks and packet-only replay of four application calls and ten actual ports. Their original declarations/modules are absent from replay. Restored dependency binaries are hash-checked, with no claim of an independent Mathlib rebuild.

- `contexts` uses the same original proof binder before and after a local definition. Its two boundary proof uses form **one source bundle**, while their native judgments remain in contexts Γ6 and Γ7. Their producer node IDs differ (13 and 15) in this pinned packet.
- `shadows` has two original proof binders with identical printed proposition `P`. Their uses remain **two source bundles**, in contexts Γ6 and Γ8. Both proof uses have stored node ID 15, but their original binder IDs are 23 and 21. Grouping by stored node ID or proposition text would incorrectly merge them. These IDs are packet-local; the tests use qualified routes.

Both two-call regions also pass the complete finite source-use graph check. These are distinct native provenance cases, not a statement that proof terms with equal types are semantically interchangeable. Only authored synthetic source, compiled term data and verification metadata are added. Private research proof scripts and raw execution logs remain outside publication.

## Riccati case

The five boundary proof inputs are recorded as:

1. `0 ≤ |J.T1 p|` in Γ10.
2. `0 ≤ |J.T2 p|` in Γ10.
3. `|J.T1 p| * |J.T2 p| = (J.d p * |J.s p|) ^ 2 * (J.z p * (1 - J.z p) * J.Dz p)` in Γ9, used in Γ13.
4. The recorded square-root product identity in Γ13.
5. `√((J.d p * |J.s p|) ^ 2) = J.d p * |J.s p|` in Γ13.

These are proof-valued inputs to the chosen region, including derived facts. They are not claimed to be the theorem's independent assumptions. The original result portals remain in Γ10 and Γ13, with the final inequality unchanged. Selecting an input marks its consumer call and opens the actual original input/source/type inspector. Selecting another original result updates the marked call.

## Delivery and checks

The derived source-bundle model is bounded at 4 MiB. The reader displays four original proof input positions per page and retains at most 4 MiB of summary rows. It opens one existing native inspector window at a time, copies the recorded proposition and exact addresses, then disposes that window before moving to the next position. A native window may contain up to five fully resident computed graphs under the existing port-inspection bounds. Graphs are not retained by the completed summary page. The independently selected source/type inspector remains a separate lease. These are component bounds, not a total browser heap measurement.

Native roles, source routes, binder identity, producer/consumer contexts and owner hashes are checked against the original observation for each displayed row. No entire original source archive or native batch is requested. Missing observations remain unavailable, and all original input controls remain accessible. Source changes, view changes and release retire pending summary loads; an obsolete load cannot fill a new source's panel.

The independent reference check covers 102 retained cuts in 39 native profiles, all 150 proof-valued boundary positions in those cuts, exact native proposition/type-address comparisons, complete boundary recovery, canonical source grouping, tampering/concurrency/disposal refusals and a bounded source-only cut. It records 148 source bundles across these cuts. Maximum completed page size in this finite check is 9,644 bytes, with four rows and one temporary native lease. The reference checker may read a whole native batch offline; the browser loader does not.

The production browser checks pass for all five Riccati propositions, the two native controls, nine exact input/type selections, consumer highlights, selection preservation across views, missing components, stale summary cancellation, source-only refusal, desktop/mobile and both themes. The diagram and result remain visible as the desktop input list scrolls. Eight browser suites pass. A final static stylesheet refinement corrected vertical alignment after the full production build; the two affected suites were rerun against the served stylesheet. Other compatibility reports retain matching file hashes.
