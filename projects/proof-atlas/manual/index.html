Reading the geometry of a Lean proof

The drawing starts from an expression occurrence, its ordered fields and its binding context. Larger figures compose these objects into applications, introductions and local definitions. This manual explains what each connection means, what folding preserves, and where the language remains incomplete.

The scope-and-scale examples are authored structural controls without native typing certificates. The separate method-interface experiment includes finite native checks and links to compiled proofs.

The stored expression graph and the crossing microscope are structural diagnostics. Their overall shape does not summarize the mathematical argument. Checked rules, substitutions and recursor interfaces remain specialist inspections of a selected occurrence. Clarity has not yet been measured in a reader study.

1. Read the relation before the shape

  • Solid / field: an ordered expression child. The label names its constructor port.
  • Dashed / bound-to: a variable refers to its lexical binder. It is not another child.
  • Dotted / attribute or reference: a name, level, metadata value or context identifier. Read the explicit relation label.
  • Rule bar: premises and conclusion of a typing judgment. Native evidence is required for an instantiated checked rule.

The source viewer also has frontier ports: a retained root with hidden descendants and an exact count. An external Γ boundary identifies a binder outside the cut. Neither means “missing proof”. Position and distance carry no mathematical meaning. Existing specialist views use their own labelled layouts; the key describes relations, not a metric embedding or a new proof calculus.

source identity = packet hash + root + ordered child route
computed identity = evidence/derivation hash + namespace + computed route

A stored DAG node may occur more than once, under different binders. Select an occurrence route, not just a node number. A type or substitution result has its own namespace; it does not acquire a source location merely by looking similar.

2. Inspect scope, then change scale

Select an occurrence to inspect its original path and outgoing fields. For a bound variable, follow its binder. Focus a subtree to move that binder outside the cut. Toggle folding and depth to check the accounting identity.

4. Composition without losing the term

    

      
Ordered binder telescope Tₙ
$$\begin{gathered}\underbrace{\lambda (x_1:A_1)\ldots\lambda(x_n:A_n),\,t}_{n\text{ retained binders}}\\\longmapsto\quad T_n\,[x_1:A_1,\ldots,x_n:A_n]\ ;\ t\end{gathered}$$
Retain each binder's original route, kind, visibility and header regions. Headers use the context before their binder; the continuation sees the extended context. The same rule can retain mixed lam, forallE and letE prefixes. A folded forallE remains a type binder.

      
Application spine @ₙ
$$\begin{gathered}(((h\,a_1)\,a_2)\ldots a_n)\\\longmapsto\quad\mathbin{@}_n(h; a_1,\ldots,a_n)\end{gathered}$$
Keep all original application occurrences and arguments in order. head and argN are abstract ports. Grouping performs no substitution, hides no implicit argument and proves no saturation or logical inference. A capped spine explicitly retains the remaining function region.

      
Exact cut and frontier
$$N_{\mathrm{retained}}+\sum_{R\in\mathcal F}|R|=|t|$$
A large count is stored exactly. Expanding a frontier refines one region while preserving the selected root and its scope interface. Counts measure syntax occurrences, not proof difficulty, premise necessity or time to understand a proof.

      
Shared terms, separate occurrences
$$\begin{gathered}e_k\text{ at }r_1\text{ in }\Gamma_1\\ e_k\text{ at }r_2\text{ in }\Gamma_2\end{gathered}$$
Storage sharing does not merge lexical meaning. A source reference or context module keeps its own provenance and explicit original-use mapping. Computed substitution must avoid capture; descendants do not inherit a new native judgment.

      
Source context C[p]
$$\begin{gathered}t=C_p[s]\\ |t|=|p|+\sum_{R\in\mathrm{sides}(p)}|R|+|s|\end{gathered}$$
Fold an exact constructor path into a context with one selected source region. Retain every ordered field and off-path sibling. Domains and let values precede their binder; bodies use its extension. A path can pass through type or value regions to reach a proof. Dashed connections denote source fields; they infer no intermediate typing judgment. Protocol, scope checks and limits.

5. From syntax to a checked construction

    
Read \(\Gamma\vdash t:A\) as “in context Γ, term t has type A”. The schemata below explain the notation; each concrete viewer instance needs a matching recorded judgment. \(\equiv\) denotes definitional conversion, distinct from structural identity and a proof of equality.

    

      
Π application
$$\frac{\begin{gathered}\Gamma\vdash f:\tau\quad\tau\equiv\Pi(x:A),B\\ \Gamma\vdash a:A'\quad A'\equiv A\end{gathered}}{\Gamma\vdash f\,a:\tau'\quad\tau'\equiv B[a/x]}$$
The argument type is compared with the expected domain; the result is instantiated in order. Proof/type/value roles come from recorded type information. A proof argument may become a premise, while a value argument remains a parameter.

      
Lambda introduction
$$\frac{\Gamma\vdash A:\operatorname{Sort}u\qquad\Gamma,x:A\vdash t:B}{\Gamma\vdash(\lambda(x:A),t):\Pi(x:A),B}$$
The domain is outside x's scope; the body is inside. The interface discharges x at the conclusion. It is an implication introduction only in the appropriate propositional case.

      
Local definition
$$\frac{\begin{gathered}\Gamma\vdash A:\operatorname{Sort}u\quad\Gamma\vdash v:A\\ \Gamma,x:A:=v\vdash t:B\end{gathered}}{\Gamma\vdash(\mathbf{let}\ x:A:=v;\ t):B[v/x]}$$
The type and value precede the binder. The body sees both its type and value. Native records may expose separate type-conversion and computed substitution views; their roots and evidence remain distinct from source routes.

      
Elimination and recursive premises
$$\frac{\begin{gathered}\text{parameters, motive, branch methods}\\\text{indices, major premise}\end{gathered}}{\text{recursor application}:\text{instantiated motive}}$$
A recursor needs its actual signature, constructor fields and branch contexts. This is an interface sketch, not a universal recursor typing rule. Recorded cases and recursive premises have dedicated views; arbitrary recursors and every tactic strategy are not covered by a complete automatic interpretation.

Universe edges form a separate level graph attached to sort and const. They are not term-child ports or de Bruijn binder links. \(\operatorname{Prop}=\operatorname{Sort}0\) and \(\operatorname{Type}u=\operatorname{Sort}(u+1)\). See the pinned level definition and layered Lean reference.
